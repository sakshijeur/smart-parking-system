# Beginner's Guide — Booking & Allocation Module

This explains everything from zero: what tools you need, how to install them,
and — most importantly — what each piece of code actually does and why.
Read this top to bottom before running anything.

---

## Part 1: What You're Building (in plain terms)

You're building **two separate programs** that talk to each other over the internet:

1. **The backend** — a small server (like a mini website with no visual page)
   that sits and waits for requests. When your app says "book me a slot," the
   backend figures out which slot, saves it to the database, and replies back.
2. **The frontend** — the actual app screen on your phone. It's what the
   user taps and types into. It doesn't do any "thinking" — it just asks the
   backend to do the work and shows the result.

They're separate because tomorrow, if you want a website version too, you'd
reuse the same backend and just build a new frontend for it.

## Part 2: Tools You Need to Install (one-time setup)

Install these on your laptop, in this order:

### 1. Node.js
This lets you run JavaScript outside a browser — it's what runs your backend.
- Download from https://nodejs.org (choose the LTS version)
- Check it worked: open a terminal and type `node -v` — you should see a
  version number like `v20.11.0`

### 2. MySQL
This is the actual database — the program that stores all your data
(users, slots, bookings) permanently on disk.
- Easiest option: install **XAMPP** (https://www.apachefriends.org) — it
  includes MySQL with a simple on/off switch, no complicated setup.
- After installing XAMPP, open the XAMPP Control Panel and click "Start"
  next to MySQL.

### 3. A code editor
Use **VS Code** (https://code.visualstudio.com) if you don't have one already.

### 4. Expo Go app (on your phone)
Install "Expo Go" from the Play Store / App Store. This is what lets you
preview your React Native app live on your actual phone while developing.

## Part 3: Understanding the Backend Code (file by file)

Open the `backend/` folder in VS Code. Here's what each file is for, in the
order data flows through them:

### `schema.sql` — the blueprint of your database
This file doesn't run as part of the app — you run it **once** to create
the tables. Think of a table like an Excel sheet: `Slots` is a sheet where
each row is one parking slot, `Reservations` is a sheet where each row is
one booking. The `FOREIGN KEY` lines just mean "this column's value must
match a real row in another table" — e.g. a Reservation must point to a
real Vehicle that actually exists.

### `.env.example` → `.env` — your secret settings
This holds things that shouldn't be shared publicly (your database
password) or that change between your laptop and a teammate's laptop
(which port the server runs on). You copy this file to `.env` and fill in
your own values — `.env` is never uploaded to GitHub for this reason.

### `src/config/db.js` — connects to MySQL
This file opens a "pool" of connections to your MySQL database — think of
it as a small set of open phone lines to the database, ready to be used
whenever a request comes in, instead of dialing a fresh connection every
single time (which would be slow).

### `src/utils/qr.js` — makes the QR code
Two jobs happen here:
1. **Signing**: when a booking is made, we don't just put the plain
   reservation ID into the QR code (someone could type a fake ID and
   generate their own fake QR). Instead we attach a "signature" — a scrambled
   code only your server knows how to create — so the operator's scanner
   can verify: *"yes, this QR was really generated by our server, not faked."*
2. **Image generation**: turns that signed text into an actual scannable
   QR code image.

### `src/services/allocation.js` — the brain of your module
This is the core logic you're responsible for. In plain English, here's
what it does step by step:
1. Look in the `Slots` table for slots that: belong to the right parking
   area, support the right vehicle type, and are currently `AVAILABLE`.
2. Sort them by distance, so the nearest one comes first.
3. **Lock** that row (`FOR UPDATE`) — this is important: it tells MySQL
   "don't let anyone else touch this row until I'm done." This is what
   prevents two people from being given the same slot if they book at
   the exact same second.
4. Change that slot's status to `RESERVED`.
5. Create a new row in the `Reservations` table.
6. Generate the signed QR token for that reservation.
7. If everything succeeded, `commit()` — permanently save all these
   changes together. If anything failed partway, `rollback()` — undo
   everything, so you never end up with a half-finished booking.

### `src/routes/bookings.js` — the "front desk"
This is what actually listens for requests coming in from the app. When a
request hits `POST /api/reservations`, this file reads what the app sent,
calls `allocation.js` to do the real work, and sends a reply back —
including the QR code image, so the app can display it immediately.

### `src/server.js` — starts everything
This is the file you actually run. It starts the server, tells it to
listen on a port (like 4000), and connects the `bookings.js` routes to it.

## Part 4: Running the Backend — Step by Step

1. Open a terminal in the `backend/` folder.
2. Load the database tables (only needs to be done once):
   ```
   mysql -u root -p < ../database/schema.sql
   ```
   It'll ask for your MySQL password — if you used XAMPP and never set
   one, just press Enter.
3. Create your `.env` file:
   ```
   cp .env.example .env
   ```
   Open `.env` in VS Code and set `DB_PASSWORD` to your real MySQL
   password (leave blank if you don't have one). Set `QR_SECRET` to any
   random long string, e.g. `myTestSecret12345`.
4. Install the required packages (this reads `package.json` and downloads
   everything listed there):
   ```
   npm install
   ```
5. Start the server:
   ```
   npm run dev
   ```
6. You should see: `Booking & Allocation service running on http://localhost:4000`
   That means it worked. Leave this terminal running — closing it stops
   your server.

### How to check it's really working
Open a **second** terminal (don't close the first one) and run:
```
curl http://localhost:4000/health
```
You should see `{"status":"ok"}`. If you see a connection error instead,
your server isn't running — check the first terminal for red error text.

### Test an actual booking
In that second terminal:
```
curl -X POST http://localhost:4000/api/reservations \
  -H "Content-Type: application/json" \
  -d '{"userId":1,"vehicleId":1,"vehicleType":"CAR","parkingAreaId":1,"arrivalTime":"2026-09-23 17:00:00","durationMinutes":120}'
```
You should get back a big block of text including a `reservationId` and a
`qrImage`. That means a real row was just created in your database. Run
the exact same command again — notice the slot number changes from A1 to
A2. That's the "nearest available slot" logic picking the next best slot,
since A1 is now taken.

## Part 5: Running the Frontend — Step by Step

1. Open a **new** terminal in the `frontend/` folder (keep the backend
   terminal running).
2. Install packages:
   ```
   npm install
   ```
3. Start Expo:
   ```
   npx expo start
   ```
4. A QR code appears in the terminal. Open the **Expo Go** app on your
   phone and scan it. Your app should load on your phone in a few seconds.

### Important — the localhost problem
Your phone is a completely separate device from your laptop, so it can't
reach `localhost:4000` (that means "this same device" — which, to your
phone, is the phone itself, not your laptop).

Fix: find your laptop's local network IP address —
- Windows: run `ipconfig` in terminal, look for "IPv4 Address" (e.g. `192.168.1.5`)
- Mac: run `ifconfig | grep inet` in terminal

Then open `frontend/App.js` and change this line near the top:
```js
const API_BASE = 'http://localhost:4000';
```
to:
```js
const API_BASE = 'http://192.168.1.5:4000'; // use YOUR actual IP
```
Save the file — Expo will auto-reload the app on your phone. Make sure
your phone and laptop are on the **same WiFi network**, or this won't work.

5. Tap "Find & Reserve Nearest Slot" in the app. If everything's connected
   correctly, you'll see a confirmation card appear with a QR code image.

## Part 6: Common Errors and What They Mean

| Error you see | What it means | Fix |
|---|---|---|
| `ECONNREFUSED` when running the app | Backend server isn't running, or wrong IP | Check backend terminal is still running; double-check the IP in `App.js` |
| `ER_ACCESS_DENIED_ERROR` | Wrong MySQL password in `.env` | Re-check `DB_PASSWORD` matches what you set in MySQL |
| `ER_NO_SUCH_TABLE` | You forgot to run `schema.sql` | Run the `mysql -u root -p < ../database/schema.sql` command again (from the `backend` folder) |
| App shows blank screen on phone | Metro bundler crashed | Check the `expo start` terminal for red error text |
| `NO_SLOTS_AVAILABLE` in the response | All matching slots are already RESERVED/OCCUPIED | Expected after booking all seeded slots — run `database/reset-test-data.sql` to reset, or add more slots manually |

## Part 7: What "Concurrency-Safe" Actually Means (since this is your core feature)

Imagine two people tap "Book" on Slot A1 at the exact same millisecond.
Without protection, both requests could read "A1 is AVAILABLE" at the same
time, and both would try to reserve it — resulting in a double-booking bug.

The `FOR UPDATE` line in `allocation.js` prevents this: it tells MySQL
"whoever gets here first gets to finish their entire transaction before
anyone else is allowed to even *read* this row." The second request simply
waits a few milliseconds, and by the time it runs, it correctly sees A1 is
now RESERVED and picks A2 instead.

You can actually test this is your project's standout feature — mention
in your report/demo that you specifically solved the "double booking race
condition" problem, since most basic student projects skip this entirely.
